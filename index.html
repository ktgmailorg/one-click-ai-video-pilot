How it works

Automation with an audit trail.

The model is never the release authority. Sources, outputs, model revisions, approvals, and final checksums remain visible to the people responsible for the course material.

Main pilot plannerPrismML Bonsai 27B · binary 1-bit

Topic planning defaults to a local Q1_0 model served through llama.cpp. Course prompts stay on the pilot machine, the exact model-file digest is recorded, and accepted responses are frozen. The RISC‑V reference master uses an authored storyboard and does not claim model authorship.

Local execution
01

Start with reviewed material

Bring an instructor-approved topic, source pack, research paper, document, or authored storyboard.

02

Build a traceable plan

Prepare objectives, narration, visual directions, claims, citations, and accessibility notes.

03

Review before production

Approve the exact script and evidence before narration or generated media is accepted.

04

Use explicit providers

Text, speech, images, video, transcription, and embeddings use approved local or hosted routes.

05

Freeze accepted results

Every accepted artifact is checksummed and retained for exact replay without another model call.

06

Release an accessible package

Export video, captions, transcripts, chapters, bibliography, disclosures, and QA reports.

The first pilot cohort

One focused idea. One short video. Four review moments.

Typical pilot fit
  • A concise lesson students revisit outside class
  • A research concept that benefits from visual explanation
  • A technical process difficult to communicate in slides
  • An accessibility-first alternative to an existing text resource

Contributor access

Private repository. Verified RIT contributors.

Students, faculty, and staff who want to contribute should use the pilot form with an @rit.edu address and select “Student contributor” or the closest matching role.

We verify RIT affiliation, discuss the intended contribution, and grant private repository access when the scope fits. Model weights are installed separately and never bundled with the project.

Responsible by design

Clear boundaries for an honest pilot.

The project helps people produce and review course media. It does not replace instructor judgment, accessibility review, brand authority, or publishing responsibility.

01

The current pilot is team-operated and CLI-based, not a graphical editor.

02

Pilot inputs must be instructor-approved and non-sensitive.

03

Hosted AI is never used for restricted or student-identifying data.

04

Every pilot includes script, visual, accessibility, and release review.

05

Panopto packaging is supported; publishing remains a deliberate manual step.

06

No official RIT logo treatment is applied without central brand approval.
