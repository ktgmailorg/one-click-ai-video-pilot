Step 2 · Prepare

Begin with a small, reviewable lesson.

The initial pilot is one 2–5 minute video based on instructor-approved, non-sensitive source material.

01

One learning objective

State what a student should understand or be able to do after watching.

02

Narration or objective

Provide corrected narration, or give the configured AI a learning objective and reviewed source notes for a draft transcript.

03

Reviewed sources

Include notes, extracts, citations, URLs, and pronunciations needed to verify factual claims.

04

Data classification

Identify whether the material is public, internal, or restricted before choosing providers.

Do not place these in the public interest form

Student records, grades, disability information, protected research, credentials, restricted source files, or personally identifying student material. The public form opens an email draft and is only for discussing the pilot.

Step 3 · Private GitHub access

Verified RIT participants can receive the complete source.

Repository access is optional with assisted setup. It is required for self-service installation or code contributions.

  2. 2
    Complete verification

    The project team confirms RIT affiliation and the intended pilot or contribution.

  3. 3
    Accept the invitation

    Sign into the named GitHub account and accept the private-repository invitation.

  4. 4
    Download the project

    Use GitHub Desktop for the simplest installation path, or clone the repository from a terminal.

No-command-line option

Use GitHub Desktop

  1. Install and sign into GitHub Desktop.
  2. Choose File → Clone repository.
  3. Select URL.
  4. Enter https://github.com/ktgmailorg/video-generator-rit.git.
  5. Choose a folder and select Clone.

Step 4 · Launch

After setup, begin with a double-click.

The local companion opens the browser interface. Keep its small launcher window open until production is finished.

macOS

Double-click start-studio.command

If macOS requests confirmation, choose Open. First launch may take longer while dependencies are prepared.

Windows

Double-click start-studio.bat

Keep the companion window open. Closing it stops local production and disconnects the browser interface.

Browser address

127.0.0.1:4173

This address opens only on the computer running the companion. It is not a public or campus-network server.

The public Vercel site shows examples and documentation. It does not receive your source material or run Bonsai. The local browser page connects directly to the companion and models on your computer.

Step 5 · Create

Seven choices from material to draft.

The Create button remains disabled until the configured providers pass their readiness checks.

  1. 01
    Confirm “Ready”

    If the studio reports a provider problem, contact the operator rather than bypassing the check.

  2. 02
    Name the video

    Use a descriptive course-facing title.

  3. 03
    Choose the starting mode

    Use an approved script, or ask the configured AI to draft a transcript from a topic and reviewed sources.

  4. 04
    Add reviewed source notes

    Provide the evidence needed to verify claims. Source notes are required when AI drafts the transcript.

  5. 05
    Choose a voice

    Use the configured local voice or select an available female or male preset.

  6. 06
    Choose visuals

    Use deterministic educational diagrams by default. Generated images require an approved ComfyUI route.

  7. 07
    Create the draft

    Confirm the data route, select Create draft video, and leave the companion open.

  • MP4 video
  • VTT + SRT captions
  • Transcript
  • Thumbnail
  • QA reports
  • Run lock

Step 6 · Review

A generated draft is the beginning of review—not the release.

Each approval applies to exact checksums. Changing covered material invalidates the corresponding approval so reviewers know what they actually approved.

01

Script + evidence

Verify objectives, claims, citations, equations, pronunciations, and AI disclosure.

02

Visual treatment

Check diagram accuracy, readable text, licensing, contrast, and visual descriptions.

03

Accessibility

Correct captions and transcript; confirm meaningful visuals are verbalized or described.

04

Final release

Watch the complete master and approve the exact video and accompanying package.

Troubleshooting

Start with the message you can see.

Do not send restricted material, credentials, or raw sensitive traces when requesting help.

The local studio does not open

Confirm the launcher window is still open, then visit http://127.0.0.1:4173. Stop and restart the launcher if needed. Another computer's 127.0.0.1 address will not work.

The Create button is disabled

A required provider failed its readiness check. Record the displayed message and contact the project operator. Do not bypass the check or change the data classification.

GitHub says the repository does not exist

Private repositories look unavailable until the invitation is accepted. Confirm that you are signed into the exact GitHub account invited by the project team.

Bonsai or generated visuals are unavailable

The project operator should verify the Bonsai model digest and local endpoint. Generated images additionally require the approved ComfyUI workflow. Deterministic diagrams remain available without ComfyUI.

The draft reports source or accessibility blockers

This indicates incomplete release evidence, not necessarily a failed render. Correct the source metadata, captions, descriptions, or script; generate a new draft; and repeat review.

Include in a help request

Your course or department, the displayed readiness message, the failed stage, and whether the material is public, internal, or restricted.
