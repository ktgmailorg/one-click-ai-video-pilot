Recommended faculty path

The professor should use the studio—not install the stack.

For the first pilot cohort, an AI Club project member installs and verifies the local companion on an RIT-controlled machine. The professor then uses only the browser interface. This keeps model, driver, codec, and provider maintenance out of the course workflow.

  1. 01
    Open the local studio

    Double-click the companion launcher. It starts the local service and opens 127.0.0.1:4173 in the default browser.

  2. 02
    Add reviewed material

    Paste a corrected script, or choose AI transcript drafting and provide a learning objective plus instructor-approved source notes. Text, Markdown, SRT, and VTT files can be loaded directly.

  3. 03
    Choose production options

    Select the configured local voice or an available female/male preset. Keep deterministic educational diagrams, or use the configured ComfyUI image route.

  4. 04
    Create the draft

    When requested, Bonsai first creates a recorded source-grounded transcript draft. It then structures beat titles and visual directions. The pipeline produces speech, visuals, captions, transcript, thumbnail, video, QA, and run record automatically.

  5. 05
    Review before release

    Download the draft and accessibility files. Script, visual, accessibility, and release decisions remain human approval gates.

Operational recommendation

Assisted installation first; automatic browser production afterward.

Faculty time should go toward subject accuracy and learning design. The project team owns initial setup, model updates, support, and recovery—not the routine production clicks. After launch, the professor adds the transcript and selects Create draft video; the companion runs the complete pipeline automatically. Technical faculty may self-host the identical companion when desired.

What runs locally

The browser is simple because the companion is doing the work.

The Vercel pilot page never receives the script or source pack. The local studio talks directly to the configured runtimes on the same machine and records exactly which models and artifacts were used.

Verified contributor setup

Install once. Launch with a double-click afterward.

Contributors receive the private repository and platform launcher. The macOS start-studio.command and Windows start-studio.bat launch the browser interface. The project team supplies the approved local configuration and model locations for the pilot machine. 

git clone https://github.com/ktgmailorg/video-generator-rit.git
cd video-generator-rit
npm ci

# Verify the local provider stack.
npm run rit-video -- doctor --config video.config.local.json

# Start the browser studio.
npm run studio:launch -- --config video.config.local.json
Before a Bonsai studio is marked ready
  • Node.js 22, FFmpeg, and FFprobe pass the local check.
  • The Bonsai model path and SHA-256 are configured.
  • llama.cpp responds on the loopback address.
  • The selected Piper and whisper.cpp models are installed.
  • ComfyUI is optional unless generated visuals are selected.

Data boundary

Local means local by policy, not by guesswork.

01

The companion binds to 127.0.0.1 and refuses a public network bind.

02

Restricted and student-identifying material can route only to profiles declared executionLocation: local.

03

Provider checks must pass before the Create button becomes available.

04

Normal logs exclude secrets and raw prompts; job input files use owner-only permissions.

05

The result is labeled and treated as a draft until the required review records cover its exact checksums.
